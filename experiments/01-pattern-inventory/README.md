# Experiment #1: pattern inventory

Issue: https://github.com/tarides/maquizcoatl/issues/5 — plan: `plans/01-pattern-inventory.md`.
Lab notebook: `lab/notebook.md`.

Collects the (pattern, syntax, options, encoding) triples that Oniguruma's
main hosts compile (VS Code TextMate grammars, jq, PHP mbregex), compiles
and classifies them with upstream `f95747b`, and packages them with
subjects as workloads for #11 and #12.

## Layout

| Path | Content |
|---|---|
| `pins.json`, `sources.json` | Pins (commits, tarball sha256), licences, per-grammar provenance, host compile configurations with the code they come from |
| `scripts/extract_{textmate,jq,php}.py` | Static extraction, one JSONL record per occurrence |
| `scripts/inventory.py` | Deduplication into triples, compile + classify (stock and instrumented builds, consistency check) |
| `scripts/tables.py`, `scripts/dynamic_only.py` | Criterion 3-5 tables; classification of triples seen only at run time |
| `scripts/make_instrument_patch.py`, `instrument.patch` | Counters added to a copy of upstream (BSD-2-Clause, Oniguruma copyright kept) |
| `classify.c` | Compiles each triple in a forked child (10 s alarm) and walks the parser's tree |
| `patterns/<source>.jsonl` | Distinct triples with occurrence counts, files, compile result and the 15 feature flags |
| `patterns/<source>.dynamic-only.jsonl` | Triples captured at run time but absent from the static corpus |
| `patterns/{jq,php}.occurrences.jsonl` | Raw occurrences (the VS Code one, 10 MB, is regenerated by `build.sh`) |
| `tables/tables.md`, `tables/features.csv`, `tables/summary.json` | Results |
| `workloads/` | Capture tools, `fetch.sh`, `build.sh`, and `data/` (packaged workloads) |

Sources: `vscode` is the form Oniguruma compiles (after vscode-textmate's
`\z` rewrite), `vscode-grammar-text` the text as written in the grammars,
`jq`, `php` (php-src tests and the manual; `origins` tells them apart).

## Reproducing

    WORKDIR=/some/dir/outside/the/repo sh workloads/fetch.sh
    WORKDIR=/some/dir/outside/the/repo sh workloads/build.sh

Needs a C compiler, CMake, make, Python 3 (standard library only, run with
`-I`), Node.js and npm, git and curl. `build.sh` uses `JOBS=4` by default.
About 1.5 GB in `$WORKDIR` (the full VS Code capture is 250 MB).

## Workload format

All files are JSONL, UTF-8; byte offsets are UTF-8 byte offsets into the
subject. A subject that is not valid UTF-8 is given as `subject_hex` with
`subject` null. Option values are Oniguruma's `ONIG_OPTION_*` bit values
(`oniguruma.h`).

**`data/vscode.triples.jsonl`** — one compiled triple per line:
`id`, `pattern`, `syntax` (`ONIGURUMA`), `options` (256 = `CAPTURE_GROUP`),
`encoding` (`UTF-8`).

**`data/vscode.scanners.jsonl`** — one vscode-oniguruma `OnigScanner` per line:
`scanner` (id), `members` (triple ids, in regset order).

**`data/vscode.jsonl`** — one scanner search per line:

| Field | Meaning |
|---|---|
| `scanner` | scanner id |
| `subject`, `start`, `range` | the line (with its `\n` as vscode-textmate passes it), start byte offset, range end |
| `search_options` | search-time options (vscode-textmate passes 0) |
| `lead` | `ONIG_REGSET_POSITION_LEAD` (`onig_regset_search`, subject < 1000 bytes) or `per-regex-leftmost` (each regex searched, leftmost match wins, first on ties) |
| `match_param` | null (defaults) |
| `expected` | `{index, match}` from stock `f95747b` (`workloads/replay.c`): winning member index (-1 no match, -2 a member fails to compile) and `[from, to)` of group 0 |
| `vscode_oniguruma_1_7_0` | what the host's bundled Oniguruma returned |
| `origin` | fixture file and line |

`data/` keeps the first 20 searches of each scanner (11,263 of 473,134);
`build.sh` regenerates the complete set in `$WORKDIR/out/workloads-full`.

**`data/jq.jsonl`, `data/php.jsonl`** — one `onig_search` / `onig_match` call per line:

| Field | Meaning |
|---|---|
| `kind` | `search` or `match` |
| `triple` | `{id, pattern, syntax, options, encoding}` as passed to `onig_new` |
| `subject` / `subject_hex`, `start`, `range` | as passed (range null for `match`) |
| `search_options` | options of the call |
| `match_param` | null, or `{retry_limit_in_match, match_stack_limit}` read from the `OnigMatchParam` (PHP: 1000000 / 100000 by default) |
| `expected` | `{result, match}`: the return value and `[from, to)` of group 0, from the host running on stock `f95747b` |

PHP capture limits: subjects over 4 KiB and calls past the 5000th in one
process are not logged (`summary.json` counts them); these come from a few
stress tests that loop over large strings.

**`data/summary.json`** — counts, dynamic-only triples, and the searches
where stock `f95747b` and vscode-oniguruma 1.7.0 disagree.

## Host versions

vscode-oniguruma 1.7.0 (the version VS Code pins) bundles an older
Oniguruma (the repository's submodule is at v6.9.8, `08d3611`), so the
workloads give expected results from stock `f95747b` and keep the host's
own answer alongside. jq 1.8.2 and PHP 8.5.12 are built from release
tarballs and linked against the stock `f95747b` shared library, so their
captured results are the stock results.
