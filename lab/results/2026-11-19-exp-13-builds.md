# Experiment #13, builds: pinned version against the latest release

Plan: [`plans/13-upgrade-cost.md`](../../plans/13-upgrade-cost.md)
("Part A: builds"). Issue: https://github.com/tarides/maquizcoatl/issues/3.
Decisions applied: https://github.com/tarides/maquizcoatl/issues/3#issuecomment-7017680025.

## What and why

The mining half of the experiment (summary v3:
[`2026-11-19-exp-13-mining-v3.md`](2026-11-19-exp-13-mining-v3.md))
reads a year of history. The builds half answers the issue's criteria 2 to
4 on today's code: does each of the five projects build and check
unchanged on its pinned tool version and on the latest release, what does
the port cost when it does not, and how do the wall-clock times compare.
Each project was built with Vincent Balat's driver, `upgrade_builds`
(`experiments/13-upgrade-cost/mining/`), on the bench host.

The driver's scripted bump also moved mathlib from `v4.34.0-rc1` to
`v4.36.0` (`lake update`, `lake exe cache get`). Deprecation warnings
remain (`mvcgen`, `Finset.not_mem_subset`). After the port, the build is
16% faster on v4.36.0.

### Pulse examples: the port

Patch: [`pulse-examples-v2026.11.15.patch`](2026-11-19-exp-13-builds-files/pulse-examples-v2026.11.15.patch).
`lemma_serialize_result_bytes` needs `be_to_n (n_to_be x) == x`, a
non-linear arithmetic fact; F\* v2026.11.15 times out on it at the default
rlimit with the same Z3 4.13.3, so the change is in F\*'s encoding, not in
the solver. Raising the rlimit to 40 for that one lemma is enough. The
make target stops at the first failing directory, so the unchanged run
reports one failing file; the ported run checks every example.

### Why3 gallery: what the replay measures

The 1.8.2 sessions record about 90 prover versions (Alt-Ergo 0.95.1 to
2.6.0, CVC3, CVC4 1.4 to 1.8, CVC5 1.0.0 to 1.1.2, Z3 2.19 to 4.13.2, and
many others), from years of the gallery's history. The first run, with
only the driver's provers installed (Alt-Ergo 2.6.2, CVC5 1.2.1, Z3
4.13.4), failed 430 of 453 sessions on both sides with "prover not
installed", which measures nothing. The runs above add a prover upgrade
policy to each side's `why3.conf`
([`why3-upgrade-policy.conf`](2026-11-19-exp-13-builds-files/why3-upgrade-policy.conf)):
every recorded Alt-Ergo, CVC4, CVC5 and Z3 version without an alternative
is replayed with the installed Alt-Ergo 2.6.2, CVC5 1.2.1 or Z3 4.13.4.
Both sides use exactly the same provers, so a difference between them is
a Why3 difference; a failure on both sides is a prover difference.

**Deviation from the maintainer's decision.** The decision asks for each
project's pinned prover versions, then the latest release of each prover.
Neither was done within the budget: the pinned versions are a set of
about 90 recorded versions rather than one pin, and the installed
versions (Alt-Ergo 2.6.2, CVC5 1.2.1, Z3 4.13.4) are the driver's choice,
not the provers' latest releases. Recorded as remaining work.

  next pinned run refuse to start (18:20); it was prepared again and rerun.
- Pulse, pinned and latest prepare at 18:10: failed because of the F\*

  `opam remove` before the counted runs (19:06 and 19:09).
- lean-regex: three latest runs failed before the port was complete
  (18:17, 18:20, 18:24); each pinned run before them is a repeat of the
  same measurement (83.2, 83.4, 83.4, 83.0 s).
- Why3 gallery, full, 18:20 and 18:27: no upgrade policy (430 "not
  installed" failures on both sides). Full pinned, 19:13: interrupted
  after 52 sessions by a mistake of the operator (its tmux window was
  closed).
- Why3 gallery, full, 19:21 (the counted runs): session 288,
  `prover/Prover`, was stopped on both sides at 20:24 (after 1,000 s on
  the pinned side, 17 s on the latest side), since it alone would have

  3-hour budget, at session 325 (pinned) and 319 (latest). The comparison
  uses the 317 sessions finished on both sides, `prover/Prover` excluded.

## Analysis

- Two of five projects build unchanged on the latest release: Warblre,
  and the Why3 gallery on its reduced regression list; on the full gallery
  2 of 317 sessions break on 1.9.0. Linden needs only its
  dependency moved to a commit that already exists. The two others need a
  small hand port: 24 lines in 4 files for Lean over three releases, 2
  lines for F\* over one release.
- The Lean port is the costliest and the most varied: one tactic crash
  (`grind`), one tactic interface change (`grind` anchors), and two
  `simp` normal-form changes. It is three releases (4.34 to 4.36) and about
  45 minutes of agent work; the mining figures for the same project are
  far larger (9,733 hand-written lines over ten releases, provisional)
  because they include the String API migration of 4.25 to 4.27.
- F\*: one proof that needed a higher rlimit. The F\* team's own sample
  code breaks between two consecutive releases, which matches the steady
  stream of small proof repairs in the EverParse mining rows.
- Rocq: 0 hand edits for both projects on this release step. The cost of
  following 9.3 sits in Warblre (79 lines, mining), and Linden pays it
  only by moving its pin.
- Why3: with the same provers, 1.9.0 replays almost every 1.8.2 session
  that 1.8.2 replays. Two sessions break for Why3 reasons, both seen by
  the mining: `register_allocation` uses the transformation
  `compute_specified`, renamed `compute [nodef]` in 1.9.0, and
  `division` uses a stdlib symbol (`zero`) that moved. Obsolete sessions
  still replay. Most failures on both sides come from the prover setup
  (versions and alternatives not installed, prover-upgrade timeouts), not
  from Why3.
- Wall-clock: the latest release is within ±5% of the pinned one, except
  Lean, which is 16% faster after the port. The full Why3 replay's 1.32
  is not comparable (both sides at once, on two complexes, dominated by
  prover timeouts).

## Limits

- One release step per tool (three for Lean), one project per tool, on the
  projects' latest commits: this is the cost for a project that keeps up.
  The mining entry gives the cost over a year.
- Hand-edit times are an AI agent's (Claude Code), not a human's; they
  include waiting for rebuilds.
- Why3 provers: see the deviation above.
- Absolute times are indicative (shared host, `nice`); the ratios are the
  figure to report.
