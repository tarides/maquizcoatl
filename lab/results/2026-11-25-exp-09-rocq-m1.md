## Agreement (done-criterion 2)

`vm`: `Vm.vm` on `Compile.compile r`; `sem`: `Sem.sem`; `e06`:
experiment #6's `Spec2.search` / `search_from` with `Star a` as
`Rep 0 None true a` and no backreferenced group. "search" is the
left-to-right search over start positions (`Syntax.search`, as
`search_in_range` without the optimiser) against `onig_search`; "every
start position" is one attempt at each `p = 0..|s|` against `onig_match`
at `p`. Equality is on the whole verdict: match or no match, start and
end, every group's span (unset as -1).

| Cases | Engine | search = C | every start position = C |
|---|---|---:|---:|
| fragment (50, none excluded) | vm | 50/50 | 201/201 |
| | sem | 50/50 | 201/201 |
| | e06 | 50/50 | 201/201 |
| extra probes (4) | vm | 4/4 | 10/10 |
| | sem | 4/4 | 10/10 |
| | e06 | 4/4 | 10/10 |

No disagreement, no `OutOfFuel`. The C search itself agrees with the
upstream test expectation on 50/50 ([entry 2](2026-11-25-exp-09-cases.md)).
On the probes, the VM and the semantics reproduce upstream's plain empty
check (DEV-008 on the fragment): ei04 `(a|)*` on `aa` keeps `1=2-2`
from the final empty iteration, ei11t keeps `2=0-1` from an earlier
iteration and `3=1-1` from the last.

Transcription cross-check: the fragment's semantics and experiment #6's
`Spec2.v` (which implements DEV-008 with `same_refs`,
`Spec2.v:292`) give identical verdicts on all 251 + 14 comparisons (search and start positions, fragment and probes), so
the reduction of DEV-008 to the plain check holds executably on these
cases.

## Analysis and open questions

- Run 1's exit criterion is met: the count is reported (50 upstream
  cases + 4 probes) and the Rocq VM and semantics agree with C on every
  case and every start position.
- Design choices that M2 inherits (FRAGMENT.md): fuel in the semantics
  (one unit per `compute_tree` call), with the structural measure
  `mu = (|s| - pos, sum of action weights)` written down for lemmas (c)
  and (d); the VM follows upstream's `OP_MEM_START` / `OP_MEM_START_PUSH`
  split (`regcomp.c:5819-5821`), so lemma (b) must allow stale captures
  of a non-push group until it is re-entered, the main subtlety foreseen.
- The compiler's code equals upstream's plain layout by construction and
  by reading `regcomp.c` (FRAGMENT.md section 3); it was not compared
  mechanically with the bytecode upstream emits (which also uses the
  peephole opcodes `OP_PUSH_OR_JUMP_EXACT1`, `OP_PUSH_IF_PEEK_NEXT` and
  merged `OP_STR_N`). A dump with `ONIG_DEBUG_COMPILE` would settle it;
  not in the plan, left as an option for the maintainer.
- The cases exercise the empty check only through the 4 probes; random
  differential testing of the VM against `onig_match` over generated
  fragment patterns would cover more, but is not in the plan (the
  theorem is the intended guarantee).
