# Experiment #6, entry 5: T_spec of milestone 1's semantics

**What.** Criterion 5, first half: the build time of each prover's
semantics (milestone 1, experiment #9's subset) per extraction target,
with check, extraction and compile timed separately, median of three
clean runs, peak RSS and load average per run, with experiment #7's
protocol and tool versions.

**Why.** Experiment #7 compares each Unicode table's build cost
`T_table` with `T_spec` (Decision 1 of issue #11); entry 6 settles its
provisional verdicts on these figures, read as a lower bound
(Decision 5 of this experiment's plan).

## Provenance

As [entry 1](2026-11-20-exp-06-provenance.md); `series.sh m1` (Rocq,
Lean, Why3, F\*) and `series2.sh m1` (Verus, Isabelle/HOL), phase
`tspec`, each run in a fresh build directory. What is timed:

- The semantics alone (`Spec.v`, `Spec.lean`, `spec.mlw`, `Spec.fst`,
  `spec.rs`, `Spec.thy`): no case module, no driver (plan step 9). The
  compile step builds the extracted semantics to `.cmx` (OCaml targets)
  or `.o`/`.rlib`.
- Rocq: `rocq compile -R . S Spec.v` (check), `rocq compile` of
  `ExtractSpec.v` (`Extraction "spec.ml" run_case count passes fuel0`
  with `ExtrOcamlBasic`, `ExtrOcamlNatInt`, `ExtrOcamlZInt`), then
  `ocamlfind ocamlopt -c spec.mli spec.ml`.
- Lean 4: as experiment #7, `lean -R . Spec.lean -o Spec.olean -i
  Spec.ilean` (check), `lean -R . Spec.lean -o Spec.olean -c Spec.c`
  (elaboration and C emission), `leanc -c -O3 -DNDEBUG Spec.c`; no link
  (experiment #7's Lean `T_table` includes a 0.4 s link of its driver).
- Why3: `why3 prove --type-only` (type check), `why3 prove` without a
  prover (VC generation, listed but not summed, as experiment #7),
  `why3 extract -D ocaml64 spec.Spec -o spec.ml`,
  `ocamlfind ocamlopt -package zarith -c spec.ml`.
- F\*: `fstar.exe --cache_checked_modules --cache_dir cache
  --z3version 5.3.0 Spec.fst` (fresh cache), `--codegen OCaml
  --custard_entry Spec.run_case --custard_entry Spec.passes`,
  `ocamlfind ocamlopt ... -c Prims.ml Custard.ml`.
- Verus: `verus --num-threads 4 --crate-type=lib spec.rs`
  (verification), `verus --crate-type=lib --no-verify --compile spec.rs
  -- -C opt-level=3`; no extraction step.
- Isabelle/HOL: `isabelle build -c` of a session with `Spec.thy`
  (check), of a child session whose theory runs `export_code ... in
  OCaml` (extraction; plus `isabelle export` to fetch the file, not
  timed), `ocamlfind ocamlopt -package zarith -c spec.ml`. Each session
  build includes the JVM start, the build manager and loading
  `HOL-Library.Code_Target_Numeral` on the HOL heap; `isabelle-check-base`
  times that overhead alone (a session with the same imports and no
  definitions).

## Analysis and open questions

- Milestone 1's semantics builds in 0.5-2.4 s in the five provers run
  from the command line, and in about 34 s in Isabelle, of which about
  18 s is session overhead. These are build times of a 120-300 line
  fragment: they are lower bounds on the full spec's `T_spec`, not
  estimates of it.
- Verus has no extraction step (the code is the Rust program); its
  check is the safety verification of the exec code (no functional
  spec), so its `T_spec` will grow with the proofs that experiment #9
  adds, as will every prover's.
- Isabelle and Verus have no `T_table` (experiment #7 did not cover
  them), so they are outside entry 6.
