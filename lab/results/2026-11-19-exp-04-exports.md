# exp-04 exports: stubs rebuilt with a public-only version script

## What

Experiment #4 (issue #7), export control. The C stubs of mechanisms 1a
(F\* + Pulse, KaRaMeL), 1b (F\* + Pulse, Custard) and 2 (hand-written
C) were relinked, from the sources generated in the first run, with an
anonymous GNU ld version script whose `global:` list is exactly the
public names of `symbols.tsv` (208 in the default build, 216 with
POSIX) and `local: *`. Each library was re-checked with `check-stub.sh`
(criteria 1-3), its dynamic symbol table inspected, and `data_init` and
`variadic_call` run against it. Two controls: 1b relinked with the same
script plus `-Wl,-Bsymbolic` (public data no longer preemptible), and
the Rust `cdylib` (mechanism 3) built twice, once as before (naked
trampoline, rustc's own export list) and once with the C shim's
variadic exported directly through a user version script. Also measured:
what `onig_copy_syntax` does to an `onigposix.h`-only client.

## Why

The maintainer decided on issue #7 that a drop-in exports only the
public API (208 / 216 symbols), not upstream's 114 leaked internals,
through a version script that keeps public data symbols preemptible
(no `-Bsymbolic`, no protected visibility). The results review asked
for this rebuild to turn two of its points into measured facts: the
16 / 17 stub-private symbols exported by 1a / 1b (`s_init`,
`s_mbc_enc_len`, ..., `custard_init_globals`) are an interposition
hazard, and the Custard constructor route only works while the data
symbols are preemptible (review problems 3 and 4, and its follow-up on
the Rust variadic). The `onigposix.h` check backs the deviation-log
candidate.

## Analysis

- The decision is implementable on every route measured, with one
  generated file: a version script of the public names removes all
  stub-private exports (16 for 1a, 17 for 1b) and the 114 internals,
  and changes nothing the harness sees (layouts and all binaries pass,
  including the Custard constructor route). The version script is build
  glue outside the proofs, for every mechanism.
- The Custard route depends on preemption, now measured: with the
  version script the library writes its records through the GOT, into
  the executable's copies; with `-Bsymbolic` it fills its own copies
  and the client reads zeros, and even `OnigDefaultSyntax ==
  &OnigSyntaxOniguruma` becomes false. So the export rule must be
  "version script, default visibility, no `-Bsymbolic`, no protected",
  and a test that reads data values (`data_init`) must be part of the
  drop-in checks, since `check-stub.sh`'s criterion 3 does not catch
  this. KaRaMeL's and C's static initialisers do not depend on it.
- Rust: rustc already restricts a `cdylib`'s exports to its
  `#[no_mangle]` items, so mechanism 3 needed no change. The review's
  alternative works: a user version script listing the public names
  re-exports the C variadic from the shim, so the naked trampoline is
  one route, not the only one. (The earlier `--export-dynamic-symbol`
  attempt, `m3-noexport`, does not override rustc's `local: *`; a
  version script `global:` entry does.)
- The `onigposix.h` mismatch is a memory error, not only a size
  difference: `onig_copy_syntax` (`*to = *from`,
  `upstream/src/regsyntax.c:291-294`) writes 40 bytes into the 16-byte
  object an `onigposix.h`-only client declares, 24 bytes past its end.
  Candidate entry in `spec/deviations.md`.
- Not covered: mechanism 4 (deferred), other linkers (lld, gold, mold),
  and whether a version script interacts with LTO in the real build.
