What the prototype is:

- **Calls.** Bedrock2's language has no function-pointer type:
  `cmd.call` names a function of the program, and anything else is an
  external action, `cmd.interact`, whose effect the semantics takes
  from `ext_spec` and which `ToCString` prints as a C call to a function
  of the action's name. The three indirect calls are three actions
  (`vu_call_enc_len`, `vu_call_callout`, `vu_call_apply_all`), defined
  in `shim.c`: each casts its word argument back to the client's
  function pointer, calls it, and returns the callee's `int` result
  sign-extended to a word. As for Isabelle-LLVM, the clamping and the
  branch rules stay in the verified code.
- **Callee contracts.** `VU.v` defines no `ext_spec`. It is a section
  variable, with `ext_spec.ok` (the well-formedness that bedrock2's
  program logic needs to relate a proof to an execution) and the
  contract of each action, so after the section closes each theorem
  takes them as hypotheses: the theorems hold for every shim and client
  that meet the contracts (`Print Assumptions`: closed under the global
  context; `build.sh` refuses `Axiom`, `Parameter`, `Hypothesis`,
  `admit` and `Admitted`).
- **ABI.** Every Bedrock2 value is a machine word (`br_word_t`,
  `uintptr_t`), so `abi.c` defines `proto.h`'s functions as wrappers
  that sign-extend `int` arguments, zero-extend `unsigned int`, keep
  pointers and `int64_t`, and truncate the result to `int` (each
  specification proves it is in the `int` range). `b2ext.h` declares
  the word-level names; the generated `vu.c` is compiled with it
  included, so the compiler checks the generated definitions against
  it. `layout.c` checks the struct offsets the memory predicates assume.
- **Verified code.** 32-bit fields are read with `load4` and
  sign-extended in verified code where the comparison is signed
  (`vu_char_len`'s bounds, `subject_len`); `vu_i_apply` compares
  `recorded` unsigned against 8 and `calls` for equality with
  `INT_MAX`, which is the same test as the C reference's. The slot
  accessors and the record write select the field with a chain of
  tests on the index (as Isabelle-LLVM's prototype); the read accessor
  computes `s + i` and reads one byte of the lent array
  (`load_subject_byte`, from bedrock2's `array_index_nat_inbounds`).
- **Proofs.** `straightline` (bedrock2's program logic) plus a
  conditional splitter and a word-arithmetic tactic (`wsolve`: the
  facts reverted into the goal, words turned into integers, each `mod`
  into a variable with its equation, then `lia`); `vu_i_apply`'s
  record entry is chosen from the branch hypothesis. The whole file
  checks in about 165 s. The first versions were too slow (`lia` with
  `Z.div_mod_to_equations`: minutes per function; case splits on every
  branch condition: exponential in `vu_i_apply`); the final tactic turns
  each `(if c then 1 else 0) <> 0` into a fact instead of a case.

**Trusted lines: 119** (`bedrock2/TRUSTED`, `runG/trusted.tsv`): C
shim 13; ABI mapping 59 (`b2ext.h` 16, `abi.c` 31, struct offsets 12);
callee contracts, `ext_spec.ok` and the memory predicates they use 47
(`args_at`, `subject_at`, `rec_at`, the `w` notation). The
specifications of the verified functions are not counted, including the
accessors' own preconditions (as for CN and RefinedRust).

**Callee assumptions:** the callee returns (an action's `ext_spec`
gives a postcondition for its results; no divergence is modelled);
result any `int` (`-2^31 <= signed r < 2^31`, from the shim's sign
extension); the encoding is lent the byte at `p` (whole) and gives it
back unchanged; the callout is lent the whole `args` record and the
whole subject, and gives back the record with `subject`,
`subject_len`, `pos` and `num` unchanged (slots and padding any) and
the subject with the same bytes; for (a), `respects_i_apply`: the client
preserves every property of the record that every call of
`b2_vu_i_apply` preserves (it reaches the record only through the
function it is given); `ext_spec.ok`.

**Read access:** the subject is lent whole, as in Isabelle-LLVM, CN and
RefinedRust: Bedrock2's separation logic (`sep`, `ptsto`, `array`) has
no fractional or read-only permission, so the contract says the bytes
come back the same. The read itself is in verified code.

**Re-entrancy:** (a) `b2_vu_fold_all` calls `vu_call_apply_all`, which
passes `vu_i_apply` (abi.c's wrapper of the verified `b2_vu_i_apply`)
to the client: the address is taken in trusted code, as Isabelle-LLVM.
`b2_vu_fold_all_ok` assumes `respects_i_apply` and derives the record
invariant from `b2_vu_i_apply_ok` (`i_apply_rec_wf`), the composition
Isabelle-LLVM's `vu_fold_all_composed` does. (b) `vu_get_slot`,
`vu_set_slot` and `vu_get_subject_byte` are called by name from the
client's callouts; each is proved, and `caller.c` exercises them.

## Conclusion

Bedrock2 works with a trusted shim, at 119 trusted lines (seventh of
the twelve proven tools, after Verus's 117 and before Aeneas's 122),
with the same shape as Isabelle-LLVM: both languages call
external code by name only, so a C shim makes the indirect calls and
their contracts are hypotheses. Every row of the experiment has a
verdict or a decision, so the done-criteria are met. The conclusion of
the experiment does not change: no stack is eliminated.
