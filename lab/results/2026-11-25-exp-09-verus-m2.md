## The statement's trigger (change to `verus/statement.rs`)

Run 3 wrote the statement as one quantifier, `forall|r, s, p|
#![trigger sem(0, r, s, p)] groups(r).no_duplicates() ==> p <= s.len()
==> { soundness &&& exists fs ... &&& exists fv ... }`, with the comment
"The outer trigger (`sem` at fuel 0) only names a term with r, s and p
that Verus accepts; M2's proof does not depend on it". It does: with
`main_aux(r, s, p)` proving that body for every `r`, `s`, `p`, the final
step `assert forall|r, s, p| #![trigger sem(0, r, s, p)] <the body> by
{ main_aux(r, s, p) }` verifies, but the postcondition
`main_theorem_statement()` still fails (two failing checks of
`proof.rs`, 15:20:04Z and 15:20:28Z). To refute the negated statement,
Z3 has to instantiate the asserted quantifier at the statement's skolem
constants `r0, s0, p0`, which needs the ground term `sem(0, r0, s0,
p0)`; the body contains `sem` and `vm` only under the inner quantifiers,
and in the cases where an existential is false no ground term mentions
`p0` at all. No choice of trigger on the same body fixes it (`p` occurs
outside the inner quantifiers only in `p <= s.len()`, which Verus does
not accept as a trigger). Three toy crates reproduce it
([trigger-toy.txt](2026-11-25-exp-09-verus-m2-raw/verus/trigger-toy.txt)):
a statement of the same shape fails even against an identical `assert
forall`, and passes once its body is a named spec fn used as the
trigger.

The change, the usual Verus idiom: `statement.rs` defines
`main_theorem_at(r, s, p)` whose body is run 3's body with decision 5's
hypothesis, line for line (the diff only moves it under the new
function header and adds a comment), and `main_theorem_statement() =
forall|r, s, p| #[trigger] main_theorem_at(r, s, p)`. A trigger is an
instantiation hint for the solver, not part of the formula, so the
proposition is the same, and it is still Rocq's and F\*'s. It cannot be
proved equal to the old text inside Verus for the very reason above. No
exec code depends on it (the driver rebuild gives identical verdicts).
This is recorded as a question for the maintainer, as the hypothesis of
decision 5 was after run 4.
