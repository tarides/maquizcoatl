# exp-05 runF: RefinedRust, the Creusot control check, hax F\* as its own route

## What

Run F of experiment #5, after the maintainer's decisions of 2026-11-22
on issue #13
([comment](https://github.com/tarides/maquizcoatl/issues/13#issuecomment-7082233871)): one short
run for the two pending rows (RefinedRust, Bedrock2), a check of
whether a Creusot negative control that only times out could pass as
rejected, and hax F\* listed as its own route.

- **RefinedRust: works with trusted shim (156 lines).** All eleven
  RefinedRust proofs check (seven functions of `proto.h`, two helpers,
  the `Apply` implementation and its trait inclusion), the library links
  with `caller.c` and prints `expected.txt`, both negative controls are
  rejected, Miri is clean under Stacked and Tree Borrows. The read
  accessor reads the subject through a raw pointer (`ptr::add`, then
  `ptr::read`), with a manual proof.
- **Bedrock2: still pending.** Not started in this run: the RefinedRust
  prototype took the time (see "Why Bedrock2 is pending" below).
- **Creusot: yes, a timeout could pass as a rejection; fixed.** why3find
  prints the same summary for a goal that only times out as for a
  refuted one. `creusot/build.sh` now counts a control as rejected only
  if a prover answered `Invalid` or `Unknown` on its target; both
  controls were run again under the new check and are still rejected.
- **hax F\***: listed as its own route (Rust → F\* through hax, built as
  a Rust library), in a note under the stacks, not under stack C
  (`table.md`, the plan, the results comment).

Raw data (redacted: `<shared-cache>`, `<cache>`, `<exp>`, `<harness>`,
`<home>`; checked for the host name, user names, home paths and
addresses before commit) in
[`2026-11-22-exp-05-runF-raw/`](2026-11-22-exp-05-runF-raw/).

### RefinedRust (`refinedrust/`)

| Run | Status | Time | Result |
|---|---|---|---|
| `runF/refinedrust` | 0 | 422 s (7:01 wall, 8.6 GB peak RSS) | 12 proof files checked; `caller_output=same` |
| `runF/refinedrust-control` (clamp removed) | 3 (rejected) | parallel | `char_len`: "Attempt to save an incomplete proof" (the shelved goals are `lo ≤ r` and `r ≤ hi` for the raw result `r`) |
| `runF/refinedrust-control-read` (upper bound removed) | 3 (rejected) | parallel | `get_subject_byte`: "Cannot find witness"; the open goals are `i < length bs`, `loc_a s + i ≤ loc_a s + length bs` and `i` in `isize` (`refinedrust-dev/control-read-open-goals.log`, the same control on the accessor alone, with the goals printed) |
| `runF/miri.log` | 0 | | Stacked and Tree Borrows: status 0, no warning |

What the prototype is, and what it took:

- **Design.** The hax and Creusot design: one trait per client C
  function (`EncLen`, `Callout`, `ApplyAll`), each with a RefinedRust
  trait specification; the verified functions are generic over them;
  the one implementation per trait is in `src/ffi.rs`, whose items are
  `#[rr::skip]` (the trusted shim). `IApply` implements `Apply` with
  `#[rr::default_spec]`, and RefinedRust checks that it refines the
  trait's specification (`trait_incl_IApplyasApply_...`).
- **The `&mut` struct specifications** (the draft's first fix). The
  draft's `(#(-[...]), γ)` arguments did not type-check. What works at
  `2862b1d8`: a plain struct (no `#[rr::refined_by]`), arguments
  `( *[f1; ...], γ)` and observations `(-[#f1'; ...] : plist
  place_rfnRT [...])`. With `#[rr::refined_by]` the struct becomes an
  invariant type and the proofs get stuck folding it back.
- **Arrays.** RefinedRust's automation checks a write to an array
  element behind `&mut` only at constant indices, and then cannot fold
  the array back into `array_t` (stuck at the return in every variant
  tried: dynamic index, constant index, reborrow). The prototype spells
  `slot[5]` and `from[8]` as one field per element, which has the C
  layout (asserted field by field in `ffi.rs`; Miri and the C caller
  agree). Reads through a shared reference at a constant index did
  check.
- **The read accessor** (the draft's second fix): `get_subject_byte`
  reads `args.subject.add(i as usize).read()`. Its precondition owns the
  subject's `len` bytes at `s` (`#type "s" : "<#> bs" @ "array_t (length
  bs) (int u8)"`), with `alloc_alive_witness` and `loc_in_bounds` for
  `ptr::add`; its postcondition gives both back. The proof is manual
  (`proofs/proof_get_subject_byte.v`), as minivec's `get_unchecked` in
  RefinedRust's own case studies: the evars of `ptr::add`'s liveness
  witness are instantiated by hand, `updateable_typed_array_access`
  takes the byte out of the array before `ptr::read`, a stratification
  folds the array back before the return, and two side conditions are
  closed by hand (`list_insert_id`, a byte is unchanged by the cast to
  `i32`).
- **Two other manual proofs**, each the generated template plus a few
  lines: `record_at` (the last branch needs `k = 7` from `0 ≤ k < 8`,
  and its frame entry by entry) and `i_apply` (the literal
  `2147483647` is an `i32`: RefinedRust's solvers know only `127 ≤
  MaxInt i32`). The generated templates use `rep <-! liRStep`, which
  fails at the first stuck point; the manual files use `repeat
  liRStep`, as RefinedRust's case studies do.
- **Proof time.** The first `i_apply` and `callout_step`, each one
  function with all its branches, took 15-25 minutes each in Lithium;
  the branch rules (`action`) and the record test (`can_record`) are
  now separate verified functions with their own specifications, and
  the whole crate checks in 7 minutes.
- **No proof escape.** `build.sh` refuses `rr::trust_me`, `only_spec`,
  `skip`, `shim` and `code_shim` in `lib.rs`, and `Admitted`, `admit` or
  `Axiom` in the manual proofs and the generated files.
- **RefinedRust's install works.** Its own `evenint` case study, with
  the proofs of its repository, checks with this switch (development
  log, not recorded); regenerated from scratch, the templates leave the
  goals the case study's manual proofs close.

**Trusted lines: 156** (`refinedrust/TRUSTED`, `runF/trusted.tsv`):
shims 37, C glue 99 (including the layout assertions of the field
spelling), client contracts 16 (the trait specifications of `EncLen`,
`Callout` and `ApplyAll`), the subject precondition of
`get_subject_byte` 4. As for hax, a trait specification without a
precondition counts: the C client must accept every argument, and no
implementation is checked against it.

**Callee assumptions:** may diverge (Iris partial correctness); any
result; the callout gets `*args` mutably and may leave any values in
all nine fields (the verified side restores its four); the encoding is
lent nothing; for (a), the client's apply-all function keeps the record
invariant (`0 ≤ calls`, `0 ≤ recorded ≤ 8`) and reaches the record
only through the verified function it is given; the C caller meets
`get_subject_byte`'s precondition (the subject is `subject_len` live
bytes, owned for the call).

**Read access:** the subject is lent whole (an owned `array_t` in the
precondition, given back with the same bytes), as in CN and
Isabelle-LLVM; RefinedRust has a shared reference type, but a raw
pointer's target in a specification is owned here. Unlike Verus,
Aeneas, Creusot and hax, no glue turns the pointer into a slice: the
read is in verified code.

**Re-entrancy:** (a) `fold_all` hands `IApply` (verified, refining
`Apply`'s specification) to the client's `ApplyAll`; proved under the
client contract; address taken in trusted code (`c_apply`). (b)
`vu_get_slot`, `vu_set_slot`, `vu_get_subject_byte` called by name from
the client's callout; proved, and exercised by `caller.c` and Miri.

### Creusot negative controls

- **why3find cannot tell a timeout from a refutation.** On run E's
  normal crate, every goal provable, with why3find's time limits at
  1 ms: `prove-timeout.log` shows "proof failed", "✘" for all nine
  files and "Error: 9 unproved files", the summary of a refuted goal;
  the provers answered only `Timeout` (2229) and `Valid` (1343). Run
  E's pattern (`proof failed|unproved`) would count such a control as
  rejected. The run E fix (drop `timeout` from the pattern) did not
  change that.
- **The check now.** For a negative control, `build.sh` proves the
  control's target again on its own (`cargo creusot prove TARGET
  --no-cache`) with the prover answers logged, and counts a rejection
  only if a prover answered `Invalid` or `Unknown`; only timeouts or
  resource limits exit 1 (not a rejection). On the probe crate, the
  targets alone give `Timeout` and `Valid` only (not a rejection); at
  normal limits they give `Valid` only.
- **The controls again** (`runF-b`, normal run first): clamp removed,
  `char_len` alone `Timeout=12 Unknown=15 Valid=6`, rejected; upper
  bound removed, `get_subject_byte` alone `Timeout=7 Unknown=9
  Valid=7`, rejected. The normal run proves every goal and prints
  `expected.txt`. The Creusot verdict does not change.

### hax F\* as its own route

Per the maintainer's decision, hax's F\* backend is listed as its own
route, "Rust → F\* through hax, built as a Rust library", in a note
under the stacks of `table.md`, the plan and the results comment, not
under stack C (F\* + Pulse, C through KaRaMeL). Its verdict (works with
trusted shim, 134) and the conclusion that no stack is eliminated do not
change.

### Why Bedrock2 is pending

Run F used its time on RefinedRust: the draft needed the struct
specifications redesigned, the arrays spelt as fields, a manual proof
for the raw-pointer read and two more manual proofs, and two functions
split to bring their proof time from 15-25 minutes to seconds (about
1h40 of development before the recorded run at 18:18 UTC). Bedrock2's
prototype (a trusted C shim for the three indirect calls with
`ext_spec` contracts, the seven functions in Bedrock2's language, the
`ToCString` output and an ABI wrapper to `proto.h`, as for
Isabelle-LLVM) was not started. Bedrock2 stays installed (coqutil and
bedrock2 built in run E) and pending; it is not deferred (it can be
installed) and it cannot remove a stack (stack A has two *works* routes,
VST and RefinedC).

## Conclusion

12 of the 14 rows of the experiment now have a verdict, one is "not
run" by decision (hax Lean), and Bedrock2 is the one row still pending,
so the experiment's done-criteria are not all met. RefinedRust works with
a trusted shim, at the highest trusted count of the eleven proven
tools (156), but with the read accessor in verified code. Creusot's
negative controls are now checked against timeouts.
