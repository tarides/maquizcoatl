**What.** The shared case corpus of the four features
(`lab/08-hard-features/cases/*.tsv`, experiment #2's eight-column probe
format), run through `probes/harness.c` and, for set nest limits,
`cases/nest.c`, on the Debug and the ASan/UBSan builds of `f95747b`; the

(`cases/run-cases.sh`, `cases/join.py`).

agree with the C library, and any disagreement between builds, or with
the documentation, is a deviation-log candidate.

## Analysis

- **The definition site of a called group takes a call frame.** ns01
  needs limit 4 for 3 recursive calls, and ns02 shows limit k admits
  nesting k-1: the group's own occurrence is compiled as `OP_CALL`
  (`upstream/src/regcomp.c:1704-1713`) and counts against the limit.
  The semantics models it (SEMANTICS.md, section 1).
- **Deviation-log candidate D-08-1 (documentation).**
  `upstream/doc/API:1020` says the default of
  `onig_get_subexp_call_max_nest_level` is 24; the code says 20
  (`upstream/src/regint.h:115`) and ca06 confirms 20 (nesting 19 deep
  matches, not 23). The spec states 20.
- **Confirmed behaviour (documentation vs code paths).**
  `upstream/doc/RE:367` calls `(?~absent)` "a written abbreviation of
  `(?~|(?:absent)|\O*)`", but the two compile through different code
  paths (`(?~abc)` through `make_absent_tree_for_simple_one_char_repeat`,
  `(?~|abc|\O*)` through the general `make_absent_engine`, because `\O`
  is an `ND_CTYPE` node, not the string or class that
  `is_simple_one_char_repeat` accepts). The three pairs ab02/ab05,
  ab06/ab07, ab08/ab09 agree, so the documented equivalence holds on
  the corpus; to be recorded as a confirmed behaviour, not a deviation.
- `(?~abc)` cuts the range at the *start* of the first absent match
  (ab06: `M 0-1` on `xabcx`, not `xab`), as the C wiring says and as
  `doc/RE`'s own example `(?~|345|\d*)` on `12345678` gives `12`.
- No crash, sanitizer report or Debug/ASan disagreement.
