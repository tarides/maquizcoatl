# Experiment #6, milestone 2, entry 5: T_spec of the S2 semantics (Why3, F\*)

**What.** `T_spec` of the S2 semantics of Why3 (`why3/spec2.mlw`) and
F\* (`fstar/Spec2.fst`) for their OCaml targets: check, extraction and
compile timed separately, median of three clean runs, with milestone
1's method; and the informational ratio idle `T_table` / `T_spec` for
experiment #7's seven Why3 and F\* targets (plan step 9; the settling
entry is run 2's).

**Why.** Question 2 of issue #28: does milestone 2's `T_spec`, read as
a lower bound (Decision 5 of milestone 1), settle any of experiment
#7's nine open table verdicts "in-prover"?

## Provenance

As [entry 1](2026-11-24-exp-06-m2-provenance.md). Phase `tspec` of
`why3/why3_2.sh` and `fstar/fstar2.sh`, each run in a fresh build
directory. The table module is copied into the directory and built
untimed first (Why3: type check; F\*: checked file kept in the cache),
so the timed check does not re-check it; it is also timed apart
(`*-tables` labels).

- Why3: `why3 prove --type-only spec2.mlw`, `why3 prove spec2.mlw`
  (VC generation, listed apart), `why3 extract -D ocaml64 spec2.Spec2`,
  `ocamlfind ocamlopt -package zarith -open Tables -c spec2.ml`.
  Runs 1-3 (`series-m2-1b.sh`) failed at the compile step (the extracted
  `spec2.ml` names the table module's constructors unqualified, hence
  `-open Tables`); the whole Why3 series was rerun as runs 4-6
  (`series-m2-1c.sh`), and only runs 4-6 are used below.
- F\*: `fstar.exe ... Spec2.fst` (check, `Tables` checked file
  present), `--codegen OCaml --custard_entry Spec2.run_case
  --custard_entry Spec2.passes`, `ocamlfind ocamlopt ... -c Prims.ml
  Custard.ml`. Runs 1-3 of `series-m2-1b.sh`.

## Analysis

- The S2 semantics is 1.9x (Why3, 434 against 230 lines) and 1.9x
  (F\*, 348 against 184 lines) milestone 1's; its `T_spec` grows 3.2x
  (Why3, as measured) and 6.2x (F\*), partly because of the table
  module, which the measured figures include.
- No ratio reaches 1: even with the table handling counted in
  `T_spec`, every Why3 and F\* table still costs 5-16 times the
  semantics. None of the seven targets would settle "in-prover" on
  run 1's figures; the settling entry, with Rocq and Lean, is run 2's.
- Building the restricted table module itself (24 ctypes and the fold
  map as decision trees) costs 24 s in F\* and 0.5 s in Why3, an order
  of magnitude more than F\*'s semantics: in F\*, the table, not the
  semantics, dominates a cold build.
