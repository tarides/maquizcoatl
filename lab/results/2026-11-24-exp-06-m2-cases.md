# Experiment #6, milestone 2, entry 2: the S2 cases and the tables

**What.** The S2 classification of milestone 1's extraction (4,565
upstream cases, `all.tsv`) by stack G's S2 parser (`g/g2.ml`,
`g2 classify`), with the counts per suite and kind, the out-of-subset
reasons, and the case-fold and property tables generated from the
upstream sources (plan step 1-2).

**Why.** Criterion 2 needs "the number of upstream cases in the
subset" and the count outside it with reasons; the tables are the data
the S2 semantics reads (fold map and property ranges), and their size
bears on the in-prover modes (decision 2 on issue #28).

### Tables

`gen_tables.py` reads `upstream/src/unicode_fold_data.c`
(`OnigUnicodeFolds1/2/3` up to `FOLDSn_END_INDEX`: the "LOCALE"
entries `I`/`i` and U+0130 apply when the Turkish/Azeri flag is off,
the default, `upstream/src/unicode.c:235-290`), `unicode_property_data.c`
(the `CR_*` ranges, `CodeRanges[]`, the property-name pool) and
`unicode.c` (`EncUNICODE_ISO_8859_1_CtypeTable`, used below U+0100 for
the 15 standard ctypes, `upstream/src/unicode.c:1142-1146`).

| Table | Size |
|-------|-----:|
| `tables.txt` (text, all tables) | 307,131 bytes, sha256 `653b65f7143e7e85527462696ac5da4420f3456c2ac475cb9c7db818ed3b1383` |
| case-fold map (source code point to full fold) | 1,557 entries |
| property names | 886 |
| ctypes (code-range sets) | 629 |
| ctypes used by the 1,160 emitted cases (plus 12, word, for `\b`) | 24: 1 3 4 6 8 9 10 11 12 13 14 37 56 75 81 103 131 149 173 209 231 285 290 406 |
| Why3 table module, restricted / full | 1,200,176 / 3,926,154 bytes |
| F\* table module, restricted / full | 1,100,497 / 3,659,781 bytes |

The table modules are balanced decision trees (fold map: on the code
point; property: on the ranges; dispatch: on the ctype), not list
constants (experiment #7's Why3 interpreter bug). The fold map is in
full in both variants; "restricted" keeps the 24 used ctypes, "full"
all 629 (spot check). Property-heavy subset (cases whose AST holds a
ctype or property): 162 cases.

## Analysis

- S2 is 7.9 times milestone 1's 152 cases (1,197), below the plan's
  heuristic estimate of about 1,376 because the Oniguruma-only option
  letters, the API options outside S2 and the `\x{..}` code point lists
  are counted out.
- The `\x{..}`/`\o{..}` code point lists (46 cases: 24 `x2`, 22 `e`) are
  neither in the plan's list of S2 constructs nor in its exclusions;
  this run counts them out with that reason. Including them is a
  parser-only change in stack G (a list is a literal string; in a class,
  a set of code points and ranges).
- No Ruby-syntax case exists among the upstream suites; Ruby support is
  exercised by no case.
